# goosecc: design

goosecc is a C17 + GNU compiler written in Goose: preprocessor, parser and
type checker (milestone B1), and a lowering of the typed AST to GIR at -O0
that the Goose back-end (`backend-goose/`) compiles to an ELF object in the
same process (milestone B2). The front end follows clang-20 closely enough
that three oracles can hold it to clang on every corpus file (README.md,
"Results"):

- `goosecc -E` produces the same token stream as `clang-20 -E`;
- `goosecc --layout-check` emits `_Static_assert`s on goosecc's sizes,
  alignments, member offsets and declared types, which clang-20 must accept;
- `goosecc --dump-ast` prints the expression trees in clang's terms, and
  `tests/cmp_ast.py` compares them node by node (kinds, types, implicit
  casts and their cast kinds) with `clang-20 -Xclang -ast-dump=json`.

The lowering is held to clang by running the programs: every test of the
corpora is compiled by goosecc, linked with clang-20 and run
(`tests/suite_goosecc.py`).

This page covers the structure (1), the data (2), the preprocessor (3), the
parser and semantic analysis (4), how the code fits Goose's recursion rule
(5), the AST contract (6), the lowering to GIR (7), what is not
supported (8), and what B3 did for speed (9).

## 1. Structure

One process, two passes. The preprocessor runs over the whole translation
unit first and appends every token to `tu_toks`; the parser then works on
that array with random access (it needs arbitrary lookahead only to tell a
cast from a parenthesized expression, a label from an expression, and so on).
With `-E` the tokens go to the printer instead.

## 2. Data

Everything that lives for the translation unit is a global growable array
(`T[>..]`); scratch buffers that are used as stacks are `T[>..<]`. Each global
is its own data stack (176 of them plus 6 runtime stacks with the lowering
and the back-end: `goose check --stacks`), so pushing to one never moves
another, and indices stay valid for the whole run. Nothing is freed. Each
region reserves 256 MB of address space (`build.sh`, section 9).

- **`src`**: one byte arena holding every file's text (each file once, with
  a NUL and a newline after it), the spellings of tokens built by `##` and
  stringizing, and cleaned copies of tokens that contain splices. A token's
  spelling is `(offset in src, length)`, and a **location** is an offset in
  `src`: `file_of` finds the file and `line_col` the line and column through
  the file's lazily built `line_starts`.
- **`names`**: a second arena for paths and option values.
- **Identifiers** are interned in an open-addressing table (a multiply
  hash over 8-byte words, computed by the same scan that finds the
  identifier's end; section 9). `Ident` holds the spelling, the
  current macro (or -1), the keyword and directive codes, flags.
- **`Tok`** is 16 bytes: kind, flags (start of line, leading space, no
  expand, from a system header, ...), `aux`, the spelling offset, `val` (the
  identifier id, or the spelling length), and `xloc`: the location of the
  token's outermost macro expansion, which `__LINE__` and diagnostics use.
- **Types** are uniqued in one table; a *qtype* is a `u32`, `(index << 4) |
  qualifiers` (const, volatile, restrict, _Atomic), so equal canonical types
  have equal indices and type comparison is an integer comparison. Typedef
  names are not types: a declaration's type is canonical. Function types keep
  their parameter list in `tparams`; records and enums refer to the `records`
  / `fields` / `enums` tables. Alignment overrides (`aligned`, `mode`,
  typedefs with `__attribute__((aligned))`) are separate type entries whose
  `canon` field points at the plain type. Qualifiers on an array type are
  pushed down to the element type, as clang canonicalizes them.
- **AST nodes** are 32 bytes (`kind, op, flags, ty, a, b, c, loc, v`) in one
  array; children are node indices and lists are runs in `nlist`, built in
  `nscratch` and committed when complete.
- **Symbols** (`syms`) are per declaration of an entity: kind, storage class,
  flags, type, scope depth, the definition node. Scopes are a log of bound
  symbols with marks; `id_ord`, `id_tag` and `id_label` give, per identifier,
  the innermost binding in each name space, and a symbol remembers the binding
  it shadows (`prev`), so leaving a scope restores the previous bindings.

## 3. Preprocessor

The goal was clang's `-E` token stream, quirks included, so the
implementation follows clang's Preprocessor/TokenLexer model rather than the
text-book algorithm:

- **Contexts.** A stack of file contexts and token contexts (macro
  expansions, re-injected streams). A macro is disabled while its context is
  on the stack, and a context is popped only when a token is read past its
  end, so that `f(1)(2)`-style rescans and the hide-set behaviour match. An
  identifier naming a disabled macro is marked "no expand" for good.
- **Arguments** are collected into `argtoks` (each ended by an EOF token);
  pre-expansion is lazy, in body order, and cached per argument, while the
  macro is still enabled (clang's order). `__VA_ARGS__`, `__VA_OPT__`, GNU
  named variadic parameters (`args...`) and the GNU comma elision of
  `, ## __VA_ARGS__` (only when the variadic argument is left out, and not in
  strict C99 mode with fewer than two parameters) are as in clang.
- **`##`** pastes by re-lexing the two spellings (`paste_two`) and checks
  that one token results; `#` stringizes with clang's spacing rules.
- **Directives.** `#include` / `#include_next` / `#import` with the search
  list `-iquote`, `-I`, `-isystem`, the system directories, `-idirafter`
  (`"..."` first looks next to the including file); a path cache; `#pragma
  once`; include guards detected like clang's MultipleIncludeOpt (any non-null
  directive or token outside the guard invalidates it, and the guard counts
  only if the macro was not defined at the `#ifndef`). `#if` / `#elif`
  (`#elifdef`, ...) are evaluated in `intmax_t`/`uintmax_t` like clang's
  PPExpressions; skipped blocks are scanned for directives only. `#line`,
  `#error`, `#warning`, `#ident`, `_Pragma` (deferred while an argument is
  pre-expanded, as clang does). Pragmas are printed under clang's rules
  (`once`, `GCC system_header`, `push_macro`, ... are not; `message` is
  canonicalized; `omp` lines are macro-expanded). `#pragma pack`, `ms_struct`
  and `push/pop_macro` take effect: pack and ms_struct become annotation
  tokens that the parser turns into a table of (token index, value) changes.
- **Builtin macros**: `__FILE__`, `__LINE__`, `__COUNTER__`, `__DATE__`,
  `__TIME__` (from `SOURCE_DATE_EPOCH` when set), `__INCLUDE_LEVEL__`,
  `__BASE_FILE__`, `__FILE_NAME__`, `__TIMESTAMP__`, and the `__has_include`,
  `__has_include_next`, `__has_builtin`, `__has_constexpr_builtin`,
  `__has_attribute`, `__has_c_attribute`, `__has_declspec_attribute`,
  `__has_feature`, `__has_extension`, `__has_warning`, `__has_embed`,
  `__is_identifier` and `__is_target_*` operators (`__has_cpp_attribute` is
  not defined in C, as in clang).
- **Predefined macros** come from `tools/gen_predef.py`, which records the
  output of `clang-20 -dM -E -x c /dev/null` (gnu17, -O0); goosecc derives
  the other modes from it (`-std=c89/gnu89/c99/gnu99/c11/gnu11/c17`, `-O1`
  and up, `-Os`/`-Oz`, `-pthread`, `-funsigned-char`), and the generator
  checks each of those deltas against clang. The answers to every `__has_*`
  query are probed from clang over ~142,000 candidate names taken from
  libclang's strings.
- **The printer** writes a token with a space where the source had one or
  where the two spellings would otherwise lex as one token, and follows
  source lines with newlines and line markers like clang's
  PrintPreprocessedOutput. Only the token stream is required to match.

## 4. Parser and semantic analysis

The parser is recursive descent over `tu_toks`, and semantic analysis is
done as each node is built: every expression node gets its type and value
category when it is made, and every implicit conversion is inserted at once
as an explicit node, so there is no second pass. The parts:

- **Declarations.** Declaration specifiers (all C17 type specifiers, GNU
  `__int128`, `_Float16`, `__bf16`, `_Float128`/`__float128`, `_Complex`,
  `_Atomic`, `typeof`/`__typeof__`/`typeof_unqual`, `__auto_type`,
  `_Alignas`, storage classes, `inline`, `_Noreturn`, `__thread`/
  `_Thread_local`, `__extension__`), declarators with GNU attributes in all
  their positions, K&R definitions and implicit `int` (as clang: errors in
  C99 and later unless downgraded), tentative definitions, redeclarations
  with composite types, block-scope `extern`, implicit function declarations
  (clang's rules for library builtins), `_Static_assert`, and `asm` labels.
- **Attributes** that change the types or the layout are implemented
  (`packed`, `aligned`, `mode`, `vector_size`, `ext_vector_type`,
  `transparent_union`, `ms_struct`/`gcc_struct`); `noreturn`, `weak`,
  `gnu_inline`, `cleanup`, `used`, `always_inline`, `const`, `may_alias`
  and asm labels are recorded on the symbol; the others are parsed and
  ignored (B2 will need `section`, `alias` and `visibility` recorded too).
- **Types.** Integer promotions (bit-fields promote by width, through
  assignments and prefix increments as clang's `getSourceBitField`), the
  usual arithmetic conversions including complex and `__int128`,
  compatibility and composite types, enums (underlying type `unsigned int`
  unless an enumerator is negative, as clang does for C), VLAs (each VLA type
  owns its size expression), flexible array members, vectors (GNU
  `vector_size` and clang `ext_vector_type` with swizzles).
- **Record layout** is the SysV x86-64 one as clang's
  ItaniumRecordLayoutBuilder computes it: bit-field allocation units, zero-width
  bit-fields (which affect alignment even in packed records, while unnamed
  bit-fields do not), `packed` on records and members, `aligned` on records,
  members and typedefs, `#pragma pack` (it caps member alignment), and
  `ms_struct` layout (including for unions).
- **Constants.** `fold_int` / `fold_float` evaluate integer constant
  expressions and arithmetic constants on the tree (with C's truncating
  division and remainder, unsigned wrap-around and the widths of the types);
  `sizeof`, `_Alignof` and `offsetof` are folded when the type is not
  variably modified. Null pointer constants are recognized as clang does (an
  integer constant 0, or such a value cast to unqualified `void *`).
  Initializers of objects with static storage are checked to be arithmetic or
  address constants (`init.goose`, with clang's extensions such as reads of
  `const` variables and compound literals).
- **Initializers** are parsed into a syntactic tree first; a walk resolves
  designators (including GNU ranges and anonymous members) and brace elision
  into (subobject path, value) entries, a stable sort orders them, and a
  build step produces the dense semantic initializer (6.5).
- **Builtins.** The types of clang's typed builtins come from
  `builtins_gen.goose` (generated by `tools/gen_builtins.py`, which reads
  them back from clang's AST of a call to each). The ones clang checks by
  hand get their result type in `builtins.goose`: atomics and `__sync`,
  overflow checks, `__builtin_shufflevector`, `__builtin_convertvector`,
  `__builtin_bit_cast`, the floating-point classification builtins,
  `__builtin_choose_expr`, `__builtin_types_compatible_p`,
  `__builtin_constant_p`, `__builtin_classify_type`, `__builtin_offsetof`,
  `va_*`. Builtins whose types involve `FILE` are typed once a `FILE`
  typedef is visible, as in clang.
- **Diagnostics** are `file:line:col: error: message` (to stderr), with the
  clang-20 defaults: incompatible pointer types are warnings, while
  int-conversion, implicit function declarations, implicit int and
  return-type mismatches are errors unless `-Wno-...` downgrades them.
  Warnings are printed only with `-Wall`.

## 5. Recursion under Goose's rules

Goose requires every function that is part of a call cycle to be declared
`recursive fn`, and inside a cycle it forbids nonfixed values (growable
arrays, owned strings) that are live across a call back into the cycle
(spec §7.8). The parser and the preprocessor are deeply recursive (94
functions are `recursive fn`), so the code is written so that the cycles
only ever hold fixed-size locals:

- **All growable state is global.** Token buffers, node lists, the
  initializer entries, the frames of the initializer walk, the macro
  argument buffers, the string builders: every one is a global array. A
  function in a cycle may push to them freely.
- **Global arrays used as stacks** carry their discipline in the code: a
  function records `mark = buf.len`, pushes, and resizes back to the mark
  when it is done (`nscratch` + `commit_list` for node lists, `ctxs`, `xbuf`
  with the context's `xbase`, `argtoks`/`argidx`, `pre`/`precache`,
  `streams` with `sbase`, `ifr`/`ients`/`ipath` in `init.goose`). Nested
  uses see the same buffer above their caller's part.
- **Results are indices, not slices.** Functions return node, type, symbol
  and token indices; text is returned as offsets into `src` or `names`. The
  few helpers that build text (`tname` for diagnostics, the layout and dump
  writers) write into a dedicated global buffer and are not called from a
  cycle while a previous result is still in use (the aliasing checker,
  spec §5.1, enforces this).
- **Recursive algorithms over types** (`type_name`, `compatible`,
  `composite`, the layout of nested records) either recurse with fixed
  locals only, or were rewritten as loops (the type printer is iterative).

The cost of this style is the number of global arrays (one data stack
each); NOTES.md has the details.

## 6. The AST contract

The AST is meant to be lowered to -O0 IR without any further semantic
analysis: every conversion is explicit, every node has its type, value
categories are explicit, and the forms that clang represents specially are
normalized. `tests/cmp_ast.py` checks this against clang's AST on every
corpus file, so where this section is silent, the clang AST of the same
code is the reference (node for node, see `dump.goose` for the mapping).

### 6.1 Roots

`tu_node` is an `N_TU` whose list holds, in source order, `N_FUNCDEF` (a =
symbol, b = body, v/c = parameter symbols), `N_DECL` (a = symbol, b =
initializer or 0; also for function declarations), `N_TYPEDEF`, `N_TAGDEF`,
`N_STATICASSERT`. A file-scope object may be declared several times; its
symbol is shared and at most one `N_DECL` carries an initializer
(`SF_DEFINED`); `SF_TENTATIVE` marks tentative definitions without one.
`syms[s].def` is the `N_FUNCDEF` of a defined function. Storage classes are
`syms[s].sc`; `SF_FILESCOPE`, `SF_INLINE`, `SF_WEAK`, `SF_THREAD`,
`SF_NORETURN`, `SF_GNU_EXTERN_INLINE` and the attributes in `sym_attrs`
(asm label, alignment, cleanup, ...) give the rest of the linkage
information.

### 6.2 Types and values

- `nodes[n].ty` is a qtype. Every expression is an lvalue (`NF_LVALUE`) or an
  rvalue; rvalues have unqualified types, except that a conversion to a
  pointer target keeps the target's qualifiers where clang does
  (`T *const p = 0`) and `_Atomic` is kept where it matters (Atomics, below).
- **Loads are explicit**: an lvalue used as a value is wrapped in
  `N_ICAST(CK_LVAL2RVAL)`. Arrays decay with `CK_ARRAY2PTR`, functions with
  `CK_FUNC2PTR`. Nothing else reads memory implicitly.
- **Discarded values** (expression statements, the init and increment of
  `for`, the left operand of a comma) are still lvalue-converted, as in
  clang's AST, and clang's -O0 code does load them (`x;` is a load).
- `N_ICAST` (implicit) and `N_CAST` (written) carry clang's cast kinds:
  `LVAL2RVAL, ARRAY2PTR, FUNC2PTR, NULL2PTR, INTEGRAL, INT2BOOL, INT2FLOAT,
  FLOAT2INT, FLOAT2BOOL, FLOATCAST, PTR2INT, INT2PTR, PTR2BOOL, BITCAST,
  NOOP, TOVOID, TOUNION, REAL2COMPLEX, COMPLEX2REAL, COMPLEXCAST, VECSPLAT,
  ATOMIC`. The semantics are clang's: `INTEGRAL` truncates or extends by the
  source's signedness, `INT2BOOL`/`FLOAT2BOOL`/`PTR2BOOL` compare with zero,
  `NOOP` changes only qualifiers (or the enum/int spelling), `BITCAST` is
  pointer-to-pointer or between vectors of the same size,
  `COMPLEX2REAL` takes the real part, `TOUNION` builds a union from a member
  value (GNU cast to union and transparent-union arguments).
- **Atomics**: a load of an `_Atomic` lvalue is `LVAL2RVAL` to the `_Atomic`
  type followed by `ATOMIC` to the value type; a store converts with `ATOMIC`
  to the `_Atomic` type. Compound assignments and `++`/`--` on an `_Atomic`
  lvalue keep the lvalue's `_Atomic` type: lowering must make them atomic
  read-modify-writes.

### 6.3 Expressions

Builtins that clang folds (`__builtin_constant_p`, `__builtin_classify_type`,

resolved to the selected expression.

### 6.4 Statements

`N_COMPOUND` (v/c), `N_DECL` (block-scope objects, in order; static locals
have `sc == SC_STATIC` and a constant initializer; a VLA declaration
evaluates the size expressions of its type, which are the `n` field of each
`TY_VLA` type), `N_IF`, `N_WHILE`, `N_DO`, `N_FOR` (a = `N_EXPR`, an
`N_COMPOUND` of declarations, or 0; b = condition or 0; c = increment or 0; v
= body), `N_SWITCH` (a = the promoted condition, b = body, v/c = the
`N_CASE`/`N_DEFAULT` nodes in order), `N_CASE` (v = value, already converted
to the condition's type; c = node holding the upper bound of a GNU range;
a = the statement), `N_DEFAULT`, `N_LABEL` (a = label symbol, b = statement),
`N_GOTO`, `N_IGOTO` (a = pointer), `N_BREAK`, `N_CONTINUE`, `N_RETURN` (a =
value converted to the return type, or 0), `N_EXPR`, `N_NULL`, `N_ASM` (a =
template string; op bits 1 goto, 2 volatile, 4 inline, 8 file-scope asm; v/c
= `N_ASMOP` operands: op 1 output (b = lvalue), 2 input (b = the expression
as written: lowering applies the lvalue conversion unless the constraint
takes memory), 3 clobber, 4 label (a = label symbol); a = the constraint
string). Conditions of `if`, loops and `?:` are scalar rvalues; lowering
compares them with zero.

### 6.5 Initializers

The initializer of an object (the b of its `N_DECL`, or the a of an
`N_COMPLIT`) is either an expression converted to the object's type, or an
`N_INITLIST` whose type is the (unqualified) aggregate type:

- a struct has one child per member in declaration order, except unnamed
  bit-fields, which have none (as in clang); a union has one child, the
  initialized member, whose field index + 1 is the list's `a` (0: an empty
  union initializer);
- an array has one child per element up to the last one initialized, and
  `b` = a filler node (`N_ZEROINIT` of the element type) when the array is
  longer; an array of unknown size has been completed (the list's type is
  the complete array type, and so is the symbol's);
- a member or element that was not initialized is `N_ZEROINIT` (of its
  type); explicit empty braces give an empty `N_INITLIST` instead;
- a character array initialized by a string is the `N_STRING`, with the
  array's type (the string is truncated or zero-padded to it);
- designators, ranges and brace elision are resolved: lowering never sees
  them.

Static initializers have been checked to be constant (4); lowering evaluates
them (address constants are `&designator ± integer`, possibly behind casts).

### 6.6 Functions

`N_FUNCDEF`: the symbol's type is the function type; v/c are the parameter
symbols (`SK_VAR` with `SF_PARAM`). A K&R definition (`int f(a) short a;`)
has the prototype of the promoted parameter types (`int (int)`), as in clang,
while the parameter symbols keep their declared types: lowering receives the
promoted value and converts it to the declared type, as clang's codegen does.
`syms[s].flags & SF_KRDEF` marks a function whose latest declaration is such a
definition. Labels are symbols in the function's label scope.

## 7. Lowering to GIR (B2)

`goosecc -c` lowers the typed AST of section 6 to GIR version 2
([`../gir/README.md`](../gir/README.md)) and hands the tables to the Goose
back-end in the same process: `main.goose` imports `backend-goose` as a
package (`import cg from "../../backend-goose"`), and `gen::codegen()`
calls `gir_codegen` with slices of the lowering's global arrays and writes
the bytes it returns. There is no LLVM anywhere: one Goose program
preprocesses, parses, checks, lowers and generates machine code. The
semantics are clang-20's at -O0 (its CodeGen as the C++ exporter sees it in
LLVM IR), so `tools/goovm-llc/gir_export.cpp` is the reference for how each
construct is written in GIR.

The lowering lives in namespace `gen` (so that its names cannot collide
with the front end's or the back-end's), in these files:

| file | content |
|---|---|
| `gen_ir.goose` | the GIR tables, type interning, constants, instruction emission, blocks, the function layout (`fn_finish`) |
| `gen_abi.goose` | C types as GIR types; the SysV classification and clang's coerced types (`Abi` records) |
| `gen_ops.goose` | instruction helpers with constant folding, C scalar conversions, loads/stores, GEPs, block copies, library calls |
| `gen_expr.goose` | expressions: lvalues, scalars, complex values, aggregates, conditions, assignments, compound literals, statement expressions |
| `gen_call.goose` | calls, returns, `va_arg` |
| `gen_stmt.goose` | statements, local declarations and initializers, switch, labels and gotos, cleanups, function bodies |
| `gen_glob.goose` | linkage, deferred definitions, string literals, static initializers (bytes and data relocations), address constants |
| `gen_builtin.goose` | builtins, library builtins, overflow checks, FP classification, atomics |
| `gen_asm.goose` | inline assembly: operand binding and a small AT&T assembler |
| `gen_debug.goose` | `-g`: the debug tables (compile unit, subprograms, lexical blocks, locations) |
| `gen_tu.goose` | the driver, constructors/destructors, aliases, `--emit-gir` |

### 7.1 The builder

The module tables (`m_types`, `m_insts`, `m_consts`, `m_globals`, `m_data`,
...) are global grow-only arrays of the back-end's own record structs
(`backend-goose/gir.goose`), so handing them over costs nothing. Since
`gir_codegen` stores the slices in its global `M`, Goose's aliasing check
then forbids `resize`/`clear` on them anywhere in the program (NOTES.md):
the tables only ever grow (`data_grow` appends zero pages).

A function's instructions are emitted into `f_insts` with local indices,
its static allocas into `f_allocas` (a local ref `ATAG + k`), and blocks
are numbers handed out by `new_block` and placed when `start_block` starts
them. Because a block, once started, is filled until its terminator, every
block is a contiguous run of `f_insts`, in start order. `fn_finish` lays
the function out in one pass: the allocas first (the entry block), then
the instructions, rewriting the value and block fields of each by the
opcode's operand mask (`OPM`) and the positions in `m_opnds` recorded by
`op_ref` / `op_blk`. Nothing is sorted or searched; a forward branch is
just a block number that is resolved when the function is finished.

Code after a terminator (`return`, `break`, a noreturn call) has no
insertion point; a statement without a label in it is then skipped, as
clang skips it, and anything that still needs code there gets a block
without predecessors.

Operations on constants fold (integer arithmetic, compares, casts, f32/f64
arithmetic), as LLVM's IRBuilder folds them for clang, so `x = 2 + 3`
stores 5. FP constants are deduplicated, as the exporter does, because the
back-end pools them by index.

### 7.2 Values

As in clang's CodeGen, every object lives in memory: locals and
parameters get allocas (at the alignment clang gives them: 16 for arrays of
16 bytes or more), and expressions are lowered by kind of value:

- `ex_val` gives a scalar GIR value (integers, pointers, f16/f32/f64/f80,
  vectors); `_Bool` is `i1` as a value and a byte in memory;
- `ex_cplx` gives the two parts of a complex value;
- `ex_agg(n, dst)` evaluates a struct, union or array into `dst`;
- `ex_lv` gives an `LV`: an address, a bit-field (the record address and
  the field), volatility.

Loads are explicit in the AST (`CK_LVAL2RVAL`), so every load the program
does is one GIR `LOAD`. Bit-fields are read and written through the
smallest integer covering their bytes (an `i24` for a field spanning three
bytes), with shifts and masks, so an access never touches a byte the field
does not use (clang loads the whole storage unit of the bit-field run).
Conditions are branched on directly (`&&`, `||`, `!` and compares become
branches, constant conditions fold), as clang does for `if` and `?:`
(for loop conditions it computes the value first), and the values of
`&&`, `||` and `?:` are PHIs. Complex multiplication and division follow
clang: the inline formula with a NaN check and the `__mul?c3` call,
`__div?c3`. `_Float16` arithmetic is done in float through the
`__extendhfsf2` / `__truncsfhf2` helpers, `__int128` division and FP
conversions are the compiler-rt calls (`__divti3`, `__floattidf`, ...).
VLA sizes are evaluated where the declaration (or the parameter list, or
the `sizeof`) is, kept per VLA type, and a scope with a VLA saves and
restores the stack pointer (also on `break`, `continue` and a jump back
before the declaration).

### 7.3 The calling convention

`gen_abi.goose` ports clang's `X86_64ABIInfo`: `classify` merges the
classes of the fields of each eightbyte (bit-fields, unaligned members,
unions, arrays, complex, `long double`, vectors of every size), with the
post-merge rules, and `arg_abi` keeps the register budget across the
arguments (a struct that does not fit in the remaining registers goes in
memory, as a whole). The result is one `Abi` record per argument and
return:

| kind | GIR |
|---|---|
| direct | the value; `signed char`/`short` arguments and returns are `SEXT`ed to `i32` (clang's `signext`, which the exporter makes explicit) |
| coerced | one or two parts (`i8`..`i64`, `iN` for a 3-byte tail, `f32`/`f64`, a vector) loaded from the object at offsets 0 and 8; a two-part return is a GIR struct `{t0, t1}` |
| byval | a pointer to a copy, with the size and alignment in the ABI word |
| sret | a hidden first argument; the function returns it |
| ignore | empty structs |

The parts' types need not be clang's own (an SSE eightbyte holding two
floats is a `double` where clang writes `<2 x float>`): the registers they
occupy and the bytes they carry are the same. Calls of
unprototyped functions are variadic calls (`al` is set), as clang makes
them. `va_arg` is lowered inline as clang does it (register save area
with `gp_offset`/`fp_offset`, or the overflow area, PHI of the two
addresses). `tests/c` and a randomized cross test (`tests/abi_cross.py`:
struct, union, complex, `__int128`, `long double` and variadic
signatures; callee and caller compiled by clang and goosecc in all four
combinations) check it against clang-20.

### 7.4 Globals and data

An entity with linkage is one GIR global, found by its linkage name (the
asm label, else the identifier); static locals (`f.x`), compound literals
at file scope, string literals (`.L.str.N`, identical ones shared) and
local constant initializers (`__const.f.N`, copied with one `MEMCPY`) get
private globals. Definitions are emitted as clang emits them:

- external definitions always, in source order;
- `static` functions and variables, and inline functions that are
  emitted, when something emitted refers to them (clang's deferred
  declarations: an unused static inline function in a header costs
  nothing and references nothing);
- C99 inline definitions (every file-scope declaration `inline` and none
  `extern`) not at all, GNU `extern inline` not at all, except that
  `always_inline` ones are emitted as local functions (clang inlines them
  even at -O0);
- tentative definitions as zero-filled definitions, or common symbols
  with `-fcommon`; `extern` declarations only when referenced.

Attributes that change the object: `weak`, `alias`, `visibility`,
`section` (variables and functions), `aligned`, `used`,
`constructor`/`destructor` with priorities (`.init_array.NNNNN` arrays, as
the exporter builds them), `cleanup`, `nocommon`; thread-local variables
are `TLS` globals reached through `TLSADDR`. With `-fPIC`, definitions
are preemptible (no `LOCALREF`).

A static initializer is written into the global's bytes in `m_data` by
`sinit`, which walks the dense initializer of section 6.5: integers by
`fold_int` (128-bit ones by `fold_int128`), floating-point values exactly
in their type (`static_f80` folds in long double and rounds per
operation, through C helpers; literals are converted from their spelling
with `strtod`/`strtof`/`strtold`), bit-fields by bits, strings truncated
or padded, compound literals by their initializers, flexible array members
by extending the object. Address constants (`eval_addr`) are a global plus
an addend (`&a[3].f`, `"str" + 1`, a compound literal, a function), an
integer, or label addresses: `&&l` is a `BLOCK` relocation and `&&a - &&b`
a `BLOCKDIFF32` one, whose block numbers are rewritten when the function is
laid out (that is why static locals are defined where they are declared,
inside the function being lowered). The relocations of one global are
contiguous and sorted by offset.

### 7.5 Builtins

`gen_builtin.goose` follows CGBuiltin.cpp at -O0. Library functions that
clang lowers itself are lowered when they are called by their names too
(unless the declaration is `static`, has an asm label, or `-fno-builtin`
says otherwise): `memcpy`/`memset` (inline `MEMCPY`/`MEMSET` up to 256
bytes, else the call), `memmove`, `abs`/`labs`/`llabs`, `fabs`,
`copysign`, `floor` and the other `const` math functions (folded for
constant arguments, as LLVM folds them), `alloca`, and `strlen`, `strcmp`,
`strncmp`, `memcmp` of compile-time strings (clang's constant evaluator).
The `__builtin_` operations map to GIR: bit counting (`CTLZ`, `CTTZ`,
`CTPOP`, `BSWAP`, `BITREVERSE`, `FSHL`/`FSHR`), `*_overflow` (`OVF` when
the types agree, else exact arithmetic in a wider type and a range check,
`__muloti4` for 128-bit operands), FP classification (`ISFPCLASS`),
`__builtin_setjmp`/`longjmp` (`SJLJ_*`), `va_start`/`va_copy`,
`return_address`/`frame_address`, `trap`, `unreachable`, `expect`,
`object_size` (folded for a declared object plus a constant, as clang's
constant evaluator does; else -1/0), `shufflevector`, `convertvector`, the
`_chk` functions, the SSE builtins clang's headers leave as builtins
(`maxps`, `minps`, `movmskps`, `packssdw128` and the immediate shifts as the
GIR `X86` op; `shufps`/`shufpd` as `SHUFFLE`; `cmp*ps`/`cmp*pd` as `FCMP`,
`SEXT`, `BITCAST`, as clang emits them), and
every `__sync_*`, `__atomic_*` and `__c11_atomic_*` function (`LOAD`/`STORE`
with orderings, `ATOMICRMW`, `CMPXCHG`, `FENCE`; compare-exchange loops for
the rest). `_Atomic` objects are loaded and stored atomically, and their
compound assignments are read-modify-writes.

### 7.6 Inline assembly

An empty template only evaluates its operands (an output tied to an input
gets the input's value). Any other template is bound as the exporter binds
it: fixed-register constraints (`a`, `d`, `S`, `t`, `u`, ...) as given,
`r`/`q`/`g` from the caller-saved pool, `m` as `(%reg)`, constant `i` as an
immediate, tied inputs to their outputs, symbolic names; the operands are
substituted into the template (`%0`, `%[name]`, `%k1`, `%c2`, ...) and the
result is assembled by a small AT&T assembler in Goose, which knows the
instructions the corpora use (integer moves and ALU operations with
register, memory and immediate operands, shifts, `lea`, `bsr`, `mul`,
`bswap`, SSE scalar arithmetic, x87 `fsqrt`/`fpatan`/..., `rdtsc`,
`cpuid`, fences). The machine code and the bindings become a `GirAsm`
record, exactly what the exporter produces with LLVM's MC layer. A
template outside that subset is an error with the text that could not be
assembled. File-scope `asm` is not supported (the exporter rejects module
assembly too).

### 7.7 Debug locations

With `-g` the debug tables are filled as the exporter fills them from
clang's metadata: one compile unit (the main file and the compilation
directory), a subprogram per function (name, file, line), a lexical block
per nested compound statement (made the first time an instruction needs
it), and for every instruction a (line, column, scope).

The locations follow clang's CodeGen rules (`gen_debug.goose`):

- every statement except compound statements, labels and `case` labels
  sets a stop point at its first token (a declaration at its first
  token, the store of an initializer at the variable's name);
- every expression the lowering visits (`ex_val`, `ex_lv`, `ex_cplx`,
  `ex_agg`, `ex_bool`) sets the location to clang's `getExprLoc()` and
  restores the previous one when it is done, as `ApplyDebugLocation`
  does: an operation is at its operator, a member access at the member, a
  subscript at its base, a call at its first token, a load at what is
  loaded; what a statement emits after its operands (a store, a branch, a
  `ret`) is at the statement;
- after a compound statement the location is its `}` (cleanups and the
  branch out of it), loop back-edges are at the loop, the condition of an
  `if` branches at the condition, the branch out of an `else` arm has no
  location, the prologue has none;
- a location inside a macro expansion, its arguments included, is the
  outermost invocation's name (clang's expansion location; the
  preprocessor records the extent of each function-like invocation).

Comparing the locations with clang-20's (through `goovm-llc --dump-gir`
of `clang -g` bitcode, instructions aligned per function) gives the same
line for 99.3% of sqlite3.c's 98,000 instructions and the same line and
column for 98.6%; what differs comes from code shape (clang's single
return block, the value-context `&&` of loop conditions) and from
parentheses, which the AST does not keep. The A1 back-end does not emit
DWARF from these tables yet (`gir/README.md`), so the objects of `-g` and
of `-O0` are the same code.

## 8. Not supported

- `_BitInt(N)` (a clang extension in C17; no corpus file uses it) and C23
  syntax beyond what clang accepts in C17 mode (`#embed`, `constexpr`,
  `typeof` is supported).
- Objective-C, Blocks (`^`), OpenMP and OpenCL semantics (pragmas are
  passed through), Microsoft extensions beyond `ms_struct`, `__declspec`.
- Targets other than x86-64 Linux; the predefined macros are clang-20's for
  `x86_64-pc-linux-gnu` (no `-m`/`-march` deltas: the AVX-512 unit tests that
  need them are skipped by the corpus definition).
- Warnings: only the diagnostics needed for clang's errors are implemented;
  the warnings goosecc prints (with `-Wall`) are a small subset of clang's.
- Long double constants are folded in double precision by the front end
  (array sizes, `#if`, `_Static_assert`); the lowering evaluates the static
  initializers of `long double` objects in long double (7.4).
- In the lowering: `__float128` values (GIR has no fp128 type; an error),
  file-scope `asm`, inline assembly outside the assembler's subset, the
  SSE/AVX builtins that clang's headers leave as builtins other than those
  listed in 7.5 (`__builtin_ia32_cmpltss` and the other scalar compares,
  most AVX ones: an error naming the builtin), `-O1` and higher (accepted,
  code is -O0's), `__builtin_dynamic_object_size` (folded like
  `__builtin_object_size`, never computed at run time).

change below keeps the `-E` output, the diagnostics, the AST dump, the
layout check and the objects (with and without `-g`) byte-identical over
the 2,357 corpus files (a differential check of the six outputs against
the B2 binary's, run after each commit), and the oracles of README.md
pass as before.

tree, and `qbench` ran all 21 binaries and tcc file by file, interleaved,

### 9.1 The process

A one-line file took 2.7 ms at B2's end; it takes 1.3-1.4 ms now (tcc
1.5 ms), and CTMark's 284 files pay that start-up and exit once each.

- **Static tables.** The builtin types (1,431 names) and the seven
  `__has_*` tables were dictionaries filled at start-up from the
  generated text. `tools/gen_tables.py` now computes open-addressing
  tables over those texts (offsets and slots as `const` arrays, which
  Goose emits as static data), and `tbl_find` probes them with the
  identifier's own hash.
- **Regions.** Each global growable array is a region of reserved
  address space. `build.sh` reserves 256 MB per region instead of the
  default 2 GB (`--stack-reserve 256M`), so that the regions a run touches
  are closer together and share page-table pages (5% of a CTMark
  compile); a table of one translation unit may then hold 256 MB (the AST
  of sqlite3.c is 6.4 MB). The number of regions went from 227 to 182:
  scratch globals became locals, parallel arrays became arrays of
  structs (switch contexts, block layout, per-symbol lowering state),
  option strings moved into `names`, and the lowering's u32-keyed
  dictionaries share two tables (`gmap`, keyed by `table << 32 | key`,
  and the per-function `fmap`). Each region costs an `mmap`, an
  `mprotect` and an `madvise` at start-up (NOTES.md, section 10).
- **musl.** A static glibc executable spends 0.5-0.7 ms of every run in
  glibc's start-up, mostly `init_cacheinfo` probing the caches with
  `cpuid`, which traps to the hypervisor in a VM. `build.sh` links
  against musl when its static library is installed (`LIBC=glibc` for
  glibc): the same C code and the same outputs, 0.6 ms less per file
  (-8.5% on CTMark).
- **Files.** A header is read with `open`, `fstat`, one `read` of its
  size plus one byte straight into `src`, and `close` (`goosecc_read_file`),
  instead of os's 7 calls. An object replaces the old file (unlink,
  create) rather than truncating it: ext4 flushes a truncated file's
  blocks when it is closed, 0.2 ms per object. A directory that does not
  exist is remembered in the path cache, so its lookups are skipped; the
  path cache is keyed by the lookup buffer itself when the path needs no
  normalization.

### 9.2 The preprocessor

Preprocessing is two thirds of the in-process time over CTMark, because
every file reads the glibc headers again (850 ms of 1,335 ms; 72% of it in
system headers).

- **The driver's token loop** (`pp_fill`, main.goose) now does `pp_lex`'s
  work for the common tokens: from a file, it lexes identifiers (with an
  inlined probe of the identifier table) and one-character punctuators
  itself and hands everything else to `lex_file_token`; from a macro
  expansion it copies the run of tokens up to the next macro name or
  paste. Only the first token of a run can change the include-guard
  state, which it tracks in a local.
- **Keywords** get their kinds as tokens are added to `tu_toks`
  (`keywords_init` runs before preprocessing), and `#pragma pack` /
  `ms_struct` changes are recorded by token index at the same time, so the
  pass over all tokens before parsing (`prepare_tokens`) is gone.
- **Macro expansion.** A function-like macro whose body has no `#`, `##`
  or `__VA_OPT__` (`M_SIMPLE`, set by `#define`) is expanded by
  `expand_simple`, which substitutes pre-expanded arguments without the
  general path's checks; arguments are collected from token contexts
  through `ctx_next` and from files through `lex_file_token`, without
  `pp_lex`.
- **Scanning.** The lexer dispatches on a 256-entry class table. An
  identifier's end and its hash come from one C helper
  (`goosecc_ident_scan`): 16 bytes classified at a time with SSE2, and
  the hash computed over 8-byte words (`(h ^ w) * K`, then mixed so that
  every byte reaches the bits the table indexes with; `tools/gen_tables.py`
  computes the same for the static tables). The text of skipped groups
  and the rest of directive lines is searched 16 bytes at a time for the
  only characters that matter there (newline, `/`, quotes, backslash,
  NUL: `goosecc_skip_text`), and comments and line tables use std's
  `find_any` instead of the C library's `memchr`.

### 9.3 Parsing, lowering, memory

- **Integer literals.** The overflow check `v > (2^64 - 1 - d) / base`
  divided by a value Goose does not know as a constant, which it does
  through a magic number computed bit by bit before the loop (60
  iterations per literal; NOTES.md, section 10). `mul_add_overflows`
  checks with a multiplication: -1.5 ms of parsing on sqlite3.c.
- **The per-function map** of labels and `case` blocks is a dictionary
  whose `clear` walks its capacity; it is cleared only when it has
  entries.
- **Pages.** The tables that grow large (tokens, AST nodes, symbols, GIR
  instructions, the source text) commit their next 64 KB at once
  (`goosecc_prefault`: `MADV_POPULATE_WRITE`), half the cost per page of
  faulting them in one by one (0.68 against 1.2 µs in this VM, unmap
  included). The source text of a file larger than 8 KB is committed
  before it is read.

### 9.4 What did not help, and what was not done

- Inlining `ident_lookup` into the lexer, `-fno-asynchronous-unwind-tables`,
  and huge pages for the large tables (`MADV_HUGEPAGE` past their first
  megabyte: sqlite3.c's page faults went from 6,155 to 4,323, its time did
  not change) were measured and left out.
- The word-wise identifier hash executes about as many instructions as
  the byte loop for identifiers of 7 characters; it is faster because it
  has no per-byte multiply chain and no per-byte bounds check.
- **A persistent header cache** (opt-in, under `~/.cache/goosecc`) was
  designed and not finished: the unit would be a system header included
  from a user file, recorded with everything its preprocessing depends on
  (the macros it reads before defining them, with their definitions; the
  path-cache entries it finds or misses; the stat of every file and
  directory it reads or searches) and everything it produces relative to
  the state it starts in (bytes of `src` and `names`, identifiers in the
  order of their first lookup, macros, tokens, include-guard and path
  cache entries), and replayed only when every dependency matches;
  `__COUNTER__`, `__DATE__`, diagnostics, `#pragma push_macro` and the
  like would make an include uncacheable. With 72% of CTMark's
  preprocessing in system headers it could save about a third of a
  CTMark compile, but proving the replay identical (the brief's
  condition: the same `-E` output and objects with and without the
  cache) for every interaction with the include-guard, `#pragma once`
  and `#include_next` logic was more than the milestone had left, and
  the default build would not use it anyway.
- **Lowering each function right after it is parsed** would keep the
  AST in the cache (lowering is bound by cache misses on AST nodes on
  sqlite3.c, 120,000 of them in a 2 MB cache simulation), but the order of
  the globals, functions and constants in the object follows the
  whole-unit order of `lower_tu` (unconditional definitions first, then
  what they reference), which per-function lowering would change.

### 9.5 Where the time goes now

Over CTMark (`--time`, sum of the best of 3 per file): preprocessing
850 ms, parsing and type checking 244 ms, lowering 117 ms, the back-end
91 ms, writing 17 ms, and 400 ms outside the phases (process creation,
start-up and exit, 1.4 ms per file). sqlite3.c: preprocessing 14 ms,
